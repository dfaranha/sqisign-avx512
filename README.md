# theta-simd

AVX-512 implementation of $(2^n, 2^n)$-isogenies between elliptic products in
the theta model, with an application to SQIsign verification.

This is the code accompanying the paper:

> Marius A. Aardal, Diego F. Aranha, Patrick Longa and Giacomo Pope.
> *Vectorized (2,2)-Isogenies in the Theta Model Using AVX-512 and Applications to SQIsign.*

It contains:

- a code generator for AVX-512 (IFMA) arithmetic over $\mathbb{F}_p$ and
  $\mathbb{F}_{p^2}$ for Montgomery-friendly primes $p = c \cdot 2^e - 1$,
  with 2-, 4- and 8-way vectorization;
- vectorized elliptic-curve arithmetic, 2-isogeny chains, and the
  $(2,2)$-isogeny chain in the theta model (gluing, generic steps and
  splitting);
- vectorized SQIsign verification, including an AVX-512 SHAKE256.

## Branches

| Branch      | Contents |
|-------------|----------|
| `main`      | SQIsign Round 2 verification. |
| `superglue` | `main` with the Superglue approach to gluing (enabled by `-DSUPERGLUE`). |
| `v3`        | SQIsign Round 3 verification (new parameter sets, no short response isogeny, $x$-only gluing). |

## Requirements

- An x86-64 CPU with AVX-512F and AVX-512IFMA (e.g. Intel Ice Lake or later,
  AMD Zen 4 or later).
- `clang` or `gcc`, GNU `make`.
- Python 3, used to generate the field arithmetic for each security level.

## Building and running

From the repository root:

```sh
make            # builds levels 1, 3 and 5 in sequence
make lvl1       # or a single level: lvl1, lvl3, lvl5

./build/test_lvl1    # tests, including the known-answer tests in assets/
./build/bench_lvl1   # benchmarks (cycles)
```

The field arithmetic in `common/fp*.c` and `include/fp*.h` is generated by
`gen_fp2/gen.py` for one security level at a time. The Makefile regenerates it
when switching levels, so build the levels one after another rather than in
parallel. Binaries must be run from the repository root, as they read the
known-answer tests from `assets/`.

## Microbenchmarks

On this branch the Makefile defines `-DMICROB` by default, together with
`-DSUPERGLUE`. With `MICROB`, the verification benchmark in `bench_lvlN` times
the steps of the $(2,2)$-isogeny chain inside every verification and prints
their averages after the `sqisign verif` line:

| Line              | What is timed | Averaged per |
|-------------------|---------------|--------------|
| `gluing codomain` | Codomain of the gluing isogeny | chain |
| `gluing eval`     | One evaluation of a pair of points through the gluing isogeny | evaluation |
| `doublings`       | Every generic step after the gluing (doublings, codomains and evaluations) | chain |
| `splitting`       | Splitting the codomain back into elliptic curves | chain |
| `theta chain`     | The whole chain, including the doublings of the kernel before the gluing | chain |

The gluing lines time whichever gluing is built: Superglue with `-DSUPERGLUE`,
the original gluing without it. The timers read the time-stamp counter, so
disable frequency scaling (turbo) for meaningful cycle counts.

The timers add a few instructions to every verification. To benchmark
verification without them, override `CFLAGS` without `-DMICROB`, for example:

```sh
make lvl1 CFLAGS="-O3 -march=native -flto=auto -DSUPERGLUE"
```

## Layout

| Path                | Contents |
|---------------------|----------|
| `gen_fp2/`          | Python generator for the vectorized $\mathbb{F}_p$ / $\mathbb{F}_{p^2}$ arithmetic. |
| `common/`, `include/` | Vectorized field and curve arithmetic, 1-dimensional isogenies, theta-model $(2,2)$-isogenies, and SQIsign verification. |
| `shake_avx/`        | SHAKE256 using the AVX-512 Keccak permutation. |
| `sqisign/`          | Scalar code from the SQIsign reference implementation, used for parameters, encodings and as a baseline. |
| `test/`, `bench/`   | Tests and benchmarks. |
| `assets/`           | SQIsign known-answer tests. |
| `python_prototype/` | Python prototype of the vectorized algorithms. |
| `sqisign-sagemath/` | SageMath implementation of SQIsign used to generate test vectors. |
